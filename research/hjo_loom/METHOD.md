# How the HJO Loom counts are computed

A one-page account of the method behind the V5 submodule counts in this directory, for
readers who want to check them without reading the whole repository.

## No model produced these numbers

No model was trained or queried to compute any number here. Every count is exact
enumeration with Python's standard library (`int`, `fractions.Fraction`) in
[`szl_khipu/hjo_loom.py`](../../szl_khipu/hjo_loom.py), which imports nothing outside it. The code
was written with an AI coding assistant; commits record this in their `Co-Authored-By`
trailers. The counts rest on the checks below, which anyone can rerun, not on how the code
was written. The `torch-ext/` directory and the small trained models mentioned elsewhere in
this repository are unrelated to these computations.

## Setting

Let `R = F_q[[T^a, T^b]] ⊂ O = F_q[[T]]` with `gcd(a, b) = 1`, `δ = (a-1)(b-1)/2`, and
conductor `c = 2δ`, so `T^c O ⊆ R`. For `N ≥ 1` we count R-submodules `M ⊆ O^N` with
`dim_{F_q} O^N / M = m`, for `q = 2, 3` and `N = 1, 2`.

## Reduction to finite linear algebra

**Containment.** Such an `M` contains `T^{m+c} O^N`. The O-span `OM` contains `M`, so it has
colength at most `m` and contains `T^m O^N`. Then `T^{m+c} O^N ⊆ T^c (OM) = (T^c O) M ⊆ RM = M`.

So with `K = m + c`, `M` corresponds to the subspace `V = M / T^K O^N` of
`W = (O / T^K O)^N`, of codimension `m`, stable under multiplication by `T^a` and `T^b`;
conversely every such `V` comes from exactly one `M`. Stability under `T^a` and `T^b` is
the whole of the R-module condition, because `R` is generated by `T^a` and `T^b` and
`T^K` acts as zero on `W`.

## Enumeration

Index the basis `T^t ε_i` of `W` (`0 ≤ t < K`, `1 ≤ i ≤ N`) by `p = tN + (i-1)`, so
multiplication by `T^a` sends index `p` to `p + aN`. Every subspace of `W` has exactly one
basis in reduced echelon form in which each vector `w_p` has its lowest nonzero entry, a 1,
at a pivot `p`, and is zero at every other pivot.

`quot_bruteforce_counts` decides the positions from `p = NK - 1` down to `0`. Position `p`
is either a non-pivot, which adds 1 to the codimension, or a pivot with
`w_p = e_p + Σ x_j e_j` over the non-pivots `j > p`. `T^a w_p` and `T^b w_p` are supported
above `p`, so they lie in `V` exactly when they lie in the span of the pivots already fixed
above `p`. Their remainders after reduction by those vectors depend linearly on the `x_j`, so
the admissible `w_p` are the solutions of a linear system over `F_q`, and each one is
enumerated. A branch stops once its codimension exceeds `m`. By uniqueness of the reduced
echelon basis, every stable subspace is produced exactly once.

Work is capped. A run over its cap raises `BRUTE_FORCE_BUDGET_EXCEEDED`; it never returns a
partial count. The certificate uses a cap of 6,000,000 recursion steps per series.

## What it is compared with

`quot_formula_counts` expands the HJO Theorem 1.2 generating function at `L = q`,
`Z(t) = q^{N²δ} t^{Nδ} N_{a,b;N}(1/q, 1/t) / ∏_{i<N} (1 - q^i t)`, where `N_{a,b;N}(q, t)`
(`n_bivariate`) is the Huang–Lau–Ono sum over the cone of the gap poset (their eq. 1.9).
That code path shares nothing with the enumeration above except the pair `(a, b)`.
All 24 `(a, b, N, q)` series in the certificate agree term by term. The table is in the
[README](README.md#v5-census--brute-force-submodule-counts-all-equal-to-hjo-thm-12-at-l--q).

## Other independent checks

- **Second implementation.** [`research/hjo_profile/cylindric.py`](../hjo_profile/cylindric.py)
  counts bounded cylindric partitions with two enumerators of its own, written separately
  from the level-vector count used for V2. The committed test compares them on 24
  pair–rank cases. On 2026-11-19 all 396 inputs that the profile lab admits
  (11 pairs, `0 ≤ N ≤ 3`, `0 ≤ D ≤ 8`) also agreed: 396 of 396, no errors.
- **Negative controls.** `tests/test_hjo_loom.py` checks that a wrong profile and a wrong
  product exponent are detected, and that an over-budget run refuses.
- **Pruning.** The V1 search prunes by `Q > D`. That is exact because of Huang,
  [arXiv:2604.13238](https://arxiv.org/abs/2604.13238), cited in the README; the code also
  checks the needed inequalities as it runs and stops if one fails.

## Rerun it

Python 3.11 or later. The enumeration needs nothing beyond the standard library, but
importing it through the `szl_khipu` package also loads numpy, a declared package
dependency, so install the package first:

```
git clone https://github.com/szl-holdings/szl-khipu && cd szl-khipu
python3 -m pip install -e . pytest
python3 research/hjo_loom/build_certificate.py --check research/hjo_loom/hjo_certificate_v1.json
python3 -m pytest tests/test_hjo_loom.py tests/test_hjo_cylindric_profile.py
```

`--check` recomputes every number from scratch and requires byte-identical output. The two
test files gave 31 passed (102 subtests) in a fresh virtual environment on 2026-11-19.
Rerun on 2026-11-19 at commit `8925f46` with Python 3.13 on a 4-vCPU container:
`REPLAY_MATCH`, seal `9849e9b1cefdcb0ad67544cf0895f14e37cc62c93c089051b6541a76d0e7a4e7`,
71.5 s. The seal is the certificate's own domain-separated digest, recorded in its
`sha256` field; it is not the SHA-256 of the file.

## What this is not

Agreement on finitely many coefficients is evidence, not proof. The identities are theorems
of the cited papers and are formalized at [AxiomMath/HJO](https://github.com/AxiomMath/HJO),
which this work has not replayed. Nothing here is a new theorem, and nothing connects this
algebra to the physical knots of khipus.
