# How the HJO Loom counts are computed

A one-page account of the method behind the V5 submodule counts in this directory, for
readers who want to check them without reading the whole repository.

## No model produced these numbers

No model was trained or queried to compute any number here. Every count is exact
enumeration with Python's standard library (`int`, `fractions.Fraction`) in
[`szl_khipu/hjo_loom.py`](../../szl_khipu/hjo_loom.py), which imports nothing outside it. The code
was written with an AI coding assistant; commits record this in their `Co-Authored-By`
trailers. The counts rest on the checks below, which anyone can rerun, not on how the code
was written. The `torch-ext/` directory and the small trained models mentioned elsewhere in
this repository are unrelated to these computations.

## Setting

Let `R = F_q[[T^a, T^b]] ⊂ O = F_q[[T]]` with `gcd(a, b) = 1`, `δ = (a-1)(b-1)/2`, and
conductor `c = 2δ`, so `T^c O ⊆ R`. For `N ≥ 1` we count R-submodules `M ⊆ O^N` with
`dim_{F_q} O^N / M = m`, for `q = 2, 3` and `N = 1, 2`.

## Reduction to finite linear algebra

**Containment.** Such an `M` contains `T^{m+c} O^N`. The O-span `OM` contains `M`, so it has
colength at most `m` and contains `T^m O^N`. Then `T^{m+c} O^N ⊆ T^c (OM) = (T^c O) M ⊆ RM = M`.

So with `K = m + c`, `M` corresponds to the subspace `V = M / T^K O^N` of
`W = (O / T^K O)^N`, of codimension `m`, stable under multiplication by `T^a` and `T^b`;
conversely every such `V` comes from exactly one `M`. Stability under `T^a` and `T^b` is
the whole of the R-module condition, because `R` is generated by `T^a` and `T^b` and
`T^K` acts as zero on `W`.

## Enumeration

Index the basis `T^t ε_i` of `W` (`0 ≤ t < K`, `1 ≤ i ≤ N`) by `p = tN + (i-1)`, so
multiplication by `T^a` sends index `p` to `p + aN`. Every subspace of `W` has exactly one
basis in reduced echelon form in which each vector `w_p` has its lowest nonzero entry, a 1,
at a pivot `p`, and is zero at every other pivot.

`quot_bruteforce_counts` decides the positions from `p = NK - 1` down to `0`. Position `p`
is either a non-pivot, which adds 1 to the codimension, or a pivot with
`w_p = e_p + Σ x_j e_j` over the non-pivots `j > p`. `T^a w_p` and `T^b w_p` are supported
above `p`, so they lie in `V` exactly when they lie in the span of the pivots already fixed
above `p`. Their remainders after reduction by those vectors depend linearly on the `x_j`, so
the admissible `w_p` are the solutions of a linear system over `F_q`, and each one is
enumerated. A branch stops once its codimension exceeds `m`. By uniqueness of the reduced
echelon basis, every stable subspace is produced exactly once.

Work is capped. A run over its cap raises `BRUTE_FORCE_BUDGET_EXCEEDED`; it never returns a
partial count. The certificate uses a cap of 6,000,000 recursion steps per series.

## What it is compared with

`quot_formula_counts` expands the HJO Theorem 1.2 generating function at `L = q`,
`Z(t) = q^{N²δ} t^{Nδ} N_{a,b;N}(1/q, 1/t) / ∏_{i<N} (1 - q^i t)`, where `N_{a,b;N}(q, t)`
(`n_bivariate`) is the Huang–Lau–Ono sum over the cone of the gap poset (their eq. 1.9).
That code path shares nothing with the enumeration above except the pair `(a, b)`.
All 24 `(a, b, N, q)` series in the certificate agree term by term. The table is in the
[README](README.md#v5-census--brute-force-submodule-counts-all-equal-to-hjo-thm-12-at-l--q).

## Other checks

- **Second implementation.** [`research/hjo_profile/cylindric.py`](../hjo_profile/cylindric.py)
  counts bounded cylindric partitions with two enumerators of its own, written separately
  from the level-vector count used for V2. Both were written in this repository with the
  same AI coding assistant, so their agreement shows two different algorithms in one
  codebase agree; it is not an independent replication. The committed test compares them on 24
  pair–rank cases. On 2026-11-19 all 396 inputs that the profile lab admits
  (11 pairs, `0 ≤ N ≤ 3`, `0 ≤ D ≤ 8`) also agreed: 396 of 396, no errors.
- **Negative controls.** `tests/test_hjo_loom.py` checks that a wrong profile and a wrong
  product exponent are detected, and that an over-budget run refuses.
- **Pruning.** The V1 search prunes by `Q > D`. That is exact because of Huang,
  [arXiv:2604.13238](https://arxiv.org/abs/2604.13238), cited in the README; the code also
  checks the needed inequalities as it runs and stops if one fails.

## Rerun it

Python 3.11 or later. The certificate check needs only the standard library: the
builder loads `szl_khipu/hjo_loom.py` by file path, so nothing has to be installed.

```
git clone https://github.com/szl-holdings/szl-khipu && cd szl-khipu
python3 research/hjo_loom/build_certificate.py --check research/hjo_loom/hjo_certificate_v1.json
```

The tests import through the `szl_khipu` package, whose `__init__` loads numpy, so they
need the package installed:

```
python3 -m pip install -e . pytest
python3 -m pytest tests/test_hjo_loom.py tests/test_hjo_cylindric_profile.py
```

`--check` recomputes every number from scratch and requires byte-identical output. The two
test files gave 31 passed (102 subtests) in a fresh virtual environment on 2026-11-19.
Rerun on 2026-11-19 at commit `8925f46` with Python 3.13 on a 4-vCPU container:
`REPLAY_MATCH`, seal `9849e9b1cefdcb0ad67544cf0895f14e37cc62c93c089051b6541a76d0e7a4e7`,
71.5 s; with the builder loading the module by path, the same check gave `REPLAY_MATCH` in
71.2 s under a Python with no numpy installed. The seal is the certificate's own domain-separated digest, recorded in its
`sha256` field; it is not the SHA-256 of the file.

## What this is not

Agreement on finitely many coefficients is evidence, not proof. The identities are theorems
of the cited papers and are formalized at [AxiomMath/HJO](https://github.com/AxiomMath/HJO),
which this work has not replayed. Nothing here is a new theorem, and nothing connects this
algebra to the physical knots of khipus.

## Addendum (v2, 2026-11-19): every prime power q ≤ 9, and the counts as polynomials in q

[`hjo_certificate_v2.json`](hjo_certificate_v2.json) repeats the V5 comparison over GF(4),
GF(5), GF(7), GF(8) and GF(9) as well as F_2 and F_3 (V7), and reads each colength count as a
polynomial in `q` (V8). The rules above still hold: exact standard-library arithmetic, no
model, fail-closed caps, and no partial count ever recorded.

**Fields of order `p^k`.** The enumeration only adds, subtracts, multiplies and inverts field
elements, so it runs unchanged over any finite field given its tables. Element `e` of GF(q)
stands for `Σ d_i x^i` over F_p, where `d_i` are the base-`p` digits of `e`, reduced modulo
`x^2 + x + 1` (GF(4)) or `x^3 + x + 1` (GF(8)) over F_2, or `x^2 + 1` (GF(9)) over F_3. Each
modulus has degree at most 3 and no root in its prime field, so it is irreducible.
`tests/test_hjo_loom.py` checks this a second way, by forming every product of two monic
factors, and checks the field axioms on every triple of elements of every field. For a prime
`q` the tables are exactly arithmetic mod `q` (also tested), so the F_2 and F_3 path computes
what it computed before. The recursion itself is unchanged: on 15 prime-field series the new
code gave the same counts in the same number of steps as the previous one, and the v1
certificate still replays to `REPLAY_MATCH` with seal
`9849e9b1cefdcb0ad67544cf0895f14e37cc62c93c089051b6541a76d0e7a4e7`.

**Caps.** There are 112 series: the 16 (pair, rank) combinations of V5 times 7 fields. Each
runs colengths 0, 1, 2, … under one cap of 3,000,000 recursion steps shared by all its
colengths, up to colength 8. The first colength that would cross the cap is abandoned and not
recorded. The cap is half of V5's: a trial with 6,000,000 was stopped after 16.5 minutes with
all four workers still busy, and a calibration pass at 300,000 steps per series was used to
estimate the cost per step and which V8 rows a larger cap could still recover. Each V7 row
records the cumulative steps after every colength it completed. 66 series stopped at the cap
and 46 at colength 8; 643 colength counts were compared, and all agree with
`quot_formula_counts` at the same `q`.

**Polynomials in `q`.** The coefficient of `t^m` in `Z(t)` is
`Σ_j u_j(L) h_{m-j}(1, L, …, L^{N-1})` with `u_j(L) = L^{N²δ} n_{Nδ-j}(1/L)`, where `n_s` is the
`t^s` part of `N_{a,b;N}(q, t)` and `h_k` is the complete homogeneous symmetric polynomial. No
`n_s` has degree above `N²δ` (checked at run time), so the coefficient is a polynomial in `L`
of degree at most `B_m = N²δ + (N-1)m`. `quot_formula_polynomials` evaluates the formula
exactly at `L = 2, 3, …`, at `B + 4` points (`B` for the largest colength of the series),
interpolates over the rationals, and requires integer coefficients and degree at most `B_m`;
at least three points beyond those needed confirm the degree. Separately, the brute-force
counts alone, at the prime powers whose series reached colength `m`, are interpolated by the
unique polynomial of degree below the number of points. The row is RECOVERED when there are
at least degree + 1 such points and that interpolant equals the formula's polynomial
coefficient by coefficient; the points beyond degree + 1 are reported as extra checks.
Otherwise it is UNDERDETERMINED, with its point count and degree. Of 124 rows, 75 are
RECOVERED and 49 UNDERDETERMINED.

Given V7's agreement at every point, RECOVERED is what uniqueness of interpolation predicts
once there are degree + 1 points. What V8 adds is that, for those colengths, the enumeration
data alone fix every coefficient of the polynomial without using the formula, and that where
they cannot, the certificate says UNDERDETERMINED instead of fitting a curve.

**Wall time.** On this 4-vCPU container with Python 3.13, `--v2 --jobs 4 --write` took
667.1 s and `--v2 --jobs 4 --check` took 633.3 s (`REPLAY_MATCH`), on 2026-11-19. `--jobs`
only spreads series over processes: the bytes do not depend on it (`--jobs 1` and `--jobs 3`
gave identical output on a reduced plan). The test file checks the v2 seal and the
internal consistency of every row, and replays a cheap subset from scratch: (2,3) rank 1 over
all seven fields, two more rows, and V8 for (2,3) rank 1.

```
python3 research/hjo_loom/build_certificate.py --v2 --jobs 4 --check research/hjo_loom/hjo_certificate_v2.json
```

**What v2 is not.** Finite evidence, not proof. HJO Theorem 1.2 already covers every finite
field: it gives the motive, and so the point count over every F_q. Nothing here is a new
theorem, and V8 does not show that the counts are polynomials in `q`; the theorem does. The
brute force and the formula are two routes in one codebase, written with the same AI coding
assistant, so their agreement is not independent replication; neither is the cylindric
cross-check above.
